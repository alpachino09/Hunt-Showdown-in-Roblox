# Передача разработки «Серой заставы»

Обновлено 24.11.2026 (МСК). [Репозиторий](https://github.com/alpachino09/Hunt-Showdown-in-Roblox). Активная ветка `feature/04-premium-weapon-system`. Этап 4, фаза A, первичная инвентаризация. Передача подготовлена при остатке 11% в недельном окне и 98% в пятичасовом по телеметрии Codex. PR создаётся после приёмки этапа.

## Поручение и порядок

Собрать для оригинальной «Серой заставы» систему оружия на существующем цикле экспедиции. Последовательность образцов: вымышленное однозарядное переломное оружие, револьвер, рычажный карабин, затворная винтовка и ранний самозарядный пистолет. Референсы из Hunt и других игр используются для анализа читаемости действий в кадре. Дизайн, модели, движения, звук и баланс создаются для «Серой заставы». Внешние ресурсы требуют проверенного права на нужное использование и запись в ASSET_LIBRARY.md.

Сначала исследование и архитектура. Затем определения и серверное состояние, FPP/TPP, точки хвата, IK, контроллер анимаций и изолированный стенд. На первом образце проверяются удержание и ADS, отдача, открытие и закрытие, видимый переход реквизита между оружием и рукой, расход боезапаса и прерывание, синхронизация, звук и эффекты. После покадровой приёмки первого образца последовательно добавить оставшиеся четыре.

Приёмка включает визуальный контакт кистей и пальцев для FPP и TPP, работающие подвижные детали, отдельные полные и частичные циклы по типам, проверку переходов и очистки состояния, сетевой прогон с двумя клиентами, замеры производительности и подтверждённые лицензии. Состояния патронника и запаса, попадания, урон и награды подтверждает сервер. Клиент воспроизводит представление и эффекты.

## Известные ограничения

- Прототип пополняет боезапас одной транзакцией по таймеру. Воспроизведение по коду: израсходовать несколько зарядов одного из двух текущих оружий и нажать R. Для новой семьи ожидаются отдельные подтверждённые переходы и прерывание без двойного списания. Следующий шаг — описать серверные инварианты до правок существующей перезарядки.
- Стендовые жесты и визуальные руки существуют только как основа. Проверка их интеграции с текущей игровой камерой, контрактным вводом и чужим персонажем остаётся открытой.
- Облачные места и воспроизводимость перехода между ними остаются отдельным треком из NEXT_STEPS.md. Ручное прохождение, сеть, покадровая проверка и производительность именно этапа 4 ещё предстоят.

## Studio и восстановление

`./scripts/build.sh` собирает `build/GreyOutpost-Lobby.rbxl`, `build/GreyOutpost-Expedition.rbxl`, `build/GreyOutpost-Rush.rbxl` и `build/GreyOutpost-HunterLab.rbxl`. Для чтения текущих R15 и поз открыть локальный HunterLab, затем отдельно проверить экспедицию. Использовать локальную сборку для инвентаризации, сверить Rojo-владение до синхронизации. Ранее проведённые сценарии перечислены в TEST_REPORT.md и docs/ANIMATION_TEST_RESULTS.md. Новую Studio-проверку записывать с именем сборки, режимом, количеством клиентов, результатом и Output.

Исходный checkout ветки карты содержит локальные материалы параллельной работы. Для восстановления этапа 4 использовать его ветку в отдельной чистой копии.

```sh
git fetch --no-tags origin
git switch --track origin/feature/04-premium-weapon-system
git rev-parse HEAD
git ls-remote origin refs/heads/feature/04-premium-weapon-system
./scripts/check.sh
```

Если ветка уже есть локально, использовать `git switch feature/04-premium-weapon-system`. Для SHA последней контрольной точки сравнить локальный HEAD и удалённый ref. Исходный подтверждённый SHA приведён выше, историю этапа смотреть в SESSION_LOG.md и Git. Проверять `git status --short --branch` до работы и после отправки. Команды выполнять только в дереве этапа 4.
