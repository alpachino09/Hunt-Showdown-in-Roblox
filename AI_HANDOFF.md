## Цель и порядок

Разработать оригинальную оружейную систему для существующего цикла экспедиции. Порядок образцов: однозарядный «Фонарь», револьвер, рычажный карабин, затворная винтовка, ранний самозарядный пистолет. Первый образец проходит приёмку до начала следующего. Критерии: индивидуальная последовательность действий, проверяемый хват и пальцы, видимая связь реквизита с кистью и механизмом, FPP и TPP, серверный расход, отмена, звук/FX, покадровая и двухклиентная проверка, измерения. Hunt используется как художественный референс.

## Studio, ограничения и восстановление

`./scripts/check.sh` собирает пять мест и проверяет Luau. Для стенда открыть `build/GreyOutpost-WeaponLab.rbxl` через File → Open from File. MCP доступен. Прогон правок хвата использовал подтверждённую локальную копию с временно применёнными исходниками и двумя группами корректировок геометрии. Play остановлен, временные изменения восстановлены. Для новой проверки используйте свежий файл сборки.

Точки рук численно проверены в готовой позе. Критерий чистового ассета включает контакт пальцев и отсутствие пересечений в ходе открывания, взятия, вставки и закрытия, в FPP и TPP. Особое внимание уделить возврату кисти и реквизита при прерывании Insert. Отдельные модели заряда и гильзы есть, звук отсутствует. Облачные Place ID и переходы относятся к отдельному треку.

```sh
git fetch --no-tags origin
git switch --track origin/feature/04-premium-weapon-system
git rev-parse HEAD
git ls-remote origin refs/heads/feature/04-premium-weapon-system
./scripts/check.sh
```

Если ветка уже существует, используйте `git switch feature/04-premium-weapon-system` в её рабочем дереве. Перед изменениями проверьте `git status --short --branch`, а после каждого push сверяйте SHA. Ветка карты ведётся отдельно.

## Первое действие

Из свежей сборки WeaponLab сделать локальную тестовую копию и запустить те же два клиента по [сценарию](tests/studio/README.md). При пропуске фазы сравнить таблицы `server` и `observer`: это отличит пропуск на серверном таймлайне от репликации или проигрывания на наблюдателе. Убедиться, что обе копии загружены до начала проверки. Затем импортировать `assets/weapons/Lantern/LanternVisual.glb` в локальный WeaponLab. Сверить группы и pivots из `rig-layout.json`, масштаб и хват. Причина пропуска фазы пока не подтверждена.
